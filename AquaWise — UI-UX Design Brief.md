AquaWise — UI/UX Design Brief


1. Design Purpose


The AquaWise UI/UX should make water consumption tracking feel simple, modern, trustworthy, and professional.


The website should look like a real environmental technology product rather than a typical college project.


The interface should communicate:


- Water conservation
- Sustainability
- Data and insights
- Personalization
- Technology and AI
- Progress and improvement


The design should be visually appealing without becoming visually crowded.


---


2. Core Design Direction


Primary Style


Modern + Clean + Nature-focused


The design should combine:


- Clean modern layouts
- Natural environmental references
- Subtle water-inspired visuals
- Professional data visualization
- Soft blue and green accents
- Generous whitespace
- Clear typography
- Minimal but meaningful animations


Avoid making every component blue or green.


The colors should be used primarily for:


- Branding
- Important buttons
- Data highlights
- Charts
- Status indicators
- Achievement elements


The majority of the interface should remain neutral.


---


3. Visual Personality


AquaWise should feel:


- Clean
- Calm
- Trustworthy
- Intelligent
- Environmentally conscious
- Modern
- Friendly
- Professional


It should not feel:


- Childish
- Overly colorful
- Excessively futuristic
- Corporate and lifeless
- Overloaded with gradients
- Like a generic AI dashboard
- Like a basic college HTML project


---


4. Color System


Primary Colors


Use a restrained combination of:


Water Blue


Used for:


- Primary actions
- Water-related data
- Links
- Important highlights
- Brand elements


Conservation Green


Used for:


- Positive progress
- Conservation achievements
- Sustainability indicators
- Success states
- Selected environmental elements


Supporting Colors


Use:


- White
- Very light neutral backgrounds
- Dark charcoal text
- Soft gray borders
- Muted gray secondary text


Colors should have sufficient contrast and should not be used excessively.


Important rule


Blue + green should establish the identity, not dominate every component.


---


5. Typography


Use a modern, highly readable sans-serif font.


Recommended options:


- Inter
- Poppins
- Manrope
- DM Sans


The typography hierarchy should be clear.


Example


Large Heading


Strong and readable.


Section Heading


Medium emphasis.


Body Text


Comfortable reading size.


Supporting Text


Smaller and muted.


Avoid using too many different fonts.


---


6. Landing / Login Experience


The first screen should prioritize authentication, because AquaWise's dashboard, history, and personalized tracking depend on the user's account.


The entry experience should therefore feel like a polished product login experience rather than a conventional marketing homepage.


Suggested Layout


A split-screen or balanced centered layout can be used.


Visual Side


Use abstract environmental artwork representing:


- Water
- Flow
- Leaves
- Drops
- Circular systems
- Sustainability


The artwork should be abstract rather than a generic stock photograph.


Possible visual concept:


Flowing blue water shapes gradually transitioning into green organic forms.


Login Side


Display:


AquaWise


Short supporting line such as:


«Understand your water. Change your habits.»


Then:


- Email
- Password
- Login button
- Create account
- Optional "Remember me"


The login interface should remain simple.


---


7. Registration Experience


The registration page should follow the same visual language as the login page.


Fields:


- Name
- Email
- Password
- Confirm Password


The form should not appear unnecessarily long.


After registration:


Account Creation → User Type Selection


---


8. User Type Selection


The user should select between:


Household


Represented using a simple home/water icon.


Farmer / Agriculture


Represented using a farm/leaf/water icon.


Use two large but clean selection cards.


The selected card should have a subtle blue/green visual indication.


Avoid excessive illustrations or animations.


---


9. Assessment UI


The assessment should feel like a guided process, not a giant form.


Use a multi-step layout.


Example:


01 Household → 02 Activities → 03 Review → 04 Results


A progress indicator should show where the user currently is.


---


10. Form Design


Forms should use:


- Clear labels
- Helpful placeholders
- Short explanations when necessary
- Consistent spacing
- Rounded but not excessively rounded inputs
- Clear focus states
- Visible validation messages


Avoid placing too many inputs on one screen.


Group related questions together.


Example:


Bathroom Usage


Shower frequency
Shower duration
Toilet usage


Then:


Household Activities


Laundry
Kitchen
Vehicle washing
Gardening


---


11. Assessment Interaction


The interface should make users feel that they are completing a short assessment rather than filling out a complicated technical form.


Use:


- Progress indicators
- "Back" button
- "Next" button
- Save/continue functionality where practical
- Clear completion state


The primary action should always be visually obvious.


---


12. Results Page


The Results page should be one of the strongest visual parts of the application.


The user should immediately understand:


How much water am I using?


Display the estimated daily consumption prominently.


Example:


420 L/day


Then show:


- Weekly estimate
- Monthly estimate
- Water Saver Score


---


13. Consumption Visualization


Use charts to explain the results rather than presenting large amounts of raw numbers.


Recommended visualizations:


Doughnut Chart


Shows consumption distribution.


Example:


- Bathroom
- Kitchen
- Laundry
- Gardening
- Vehicle washing


Bar Chart


Allows users to compare categories.


Charts should use the AquaWise color system but remain visually restrained.


---


14. Dashboard Design


The dashboard should be minimal by default.


The user should be able to understand their current status within a few seconds.


Primary Dashboard


Display:


Water Usage


420 L/day


Water Saver Score


72/100


Current Streak


7 days


Top Recommendation


A short personalized recommendation.


---


15. Dashboard Charts


Below the summary cards, display a small number of useful charts.


Possible charts:


- Weekly consumption
- Monthly consumption
- Category breakdown
- Usage trend


Do not display every available chart simultaneously.


The dashboard should prioritize the information most useful to the user.


---


16. Detailed Information


The dashboard should provide an option such as:


View Detailed Analysis


This opens a more detailed view containing:


- Category-by-category usage
- Historical trends
- Weekly/monthly comparisons
- Previous assessments
- More detailed recommendations


This preserves the minimalist dashboard while still providing deeper information for users who want it.


---


17. Dashboard Card Design


Cards should have:


- Clean backgrounds
- Subtle borders/shadows
- Consistent spacing
- Clear hierarchy
- Small supporting icons where useful


Avoid turning every piece of information into a separate oversized card.


---


18. History Page


The History page should provide a chronological overview of assessments.


Each entry can display:


- Date
- Daily consumption
- Water Saver Score
- Change compared with previous assessment


Users should be able to select an entry to view its detailed results.


---


19. Progress & Gamification


Gamification should encourage continued engagement without overwhelming the main interface.


Streaks


Display:


7-day conservation streak


The streak should be visually noticeable but not dominate the dashboard.


---


Achievements


Possible achievements:


First Assessment


Completed your first water assessment.


Consistent Saver


Maintained a conservation streak.


Water Watcher


Regularly monitored water usage.


Conservation Milestone


Reached a predefined conservation milestone.


---


20. Badge Design


Badges should use simple icons and restrained colors.


Avoid childish cartoon-style badges.


Possible visual language:


- Water drop
- Leaf
- Shield
- Ripple
- Plant
- Circular arrows


Use green/blue accents while keeping the badge system consistent with the overall professional design.


---


21. AI Assistant


The AI Assistant should be accessible through a floating chat button.


The button can appear in the bottom-right corner.


It should be:


- Clearly recognizable
- Small enough not to obstruct content
- Consistent with the AquaWise branding
- Subtly animated when appropriate


When clicked:


Floating Button → Chat Panel


The chat panel should open without taking the user away from the current page.


---


22. AI Chat Experience


The chat interface should feel integrated into AquaWise rather than looking like a completely separate chatbot.


Possible quick actions:


- "How can I save more water?"
- "Explain my usage"
- "Why is my usage high?"
- "Give me recommendations"


The assistant can use relevant assessment information when available.


---


23. Navigation


Use two navigation patterns.


Public Pages


Use a top navigation bar.


Possible structure:


AquaWise | Home | About | Login | Sign Up


Since the authenticated experience is central to the application, public navigation should remain minimal.


---


Authenticated Dashboard


Use a left sidebar on desktop.


Navigation:


- Dashboard
- New Assessment
- History
- Detailed Analysis
- AI Assistant
- Achievements
- Profile


The sidebar should clearly indicate the current page.


---


24. Mobile Navigation


On smaller screens, the sidebar should transform into a mobile-friendly navigation system.


Possible approaches:


- Hamburger menu
- Bottom navigation for major sections
- Slide-out navigation drawer


The most frequently used sections should remain easy to access.


---


25. Responsive Design


AquaWise must work properly on:


- Desktop
- Laptop
- Tablet
- Mobile phone


The design should not simply shrink the desktop interface.


Instead, components should adapt.


Desktop


Multi-column layouts and sidebar navigation.


Tablet


Reduced columns and compact navigation.


Mobile


Single-column layouts, stacked cards, simplified charts, and mobile navigation.


---


26. Mobile Dashboard


On mobile, prioritize:


1. Water consumption
2. Water Saver Score
3. Streak
4. Recommendation
5. Chart
6. Detailed analysis


Avoid forcing users to scroll through many unnecessary cards.


---


27. Buttons


Primary buttons should use the AquaWise blue.


Examples:


Calculate My Usage


Start Assessment


View Analysis


Secondary buttons can use:


- White/neutral backgrounds
- Thin borders
- Blue text


Green should generally indicate:


- Positive progress
- Achievement
- Conservation milestones
- Successful actions


---


28. Icons


Use a consistent icon library.


Recommended style:


Simple outline or soft-rounded icons


Possible icons:


- Water drop
- Home
- Farm
- Chart
- History
- AI/chat
- Trophy
- Leaf
- User
- Settings


Do not mix multiple unrelated icon styles.


---


29. Illustrations


Illustrations should be used strategically.


Good locations:


- Login page
- Empty states
- Assessment introduction
- Achievement section
- Error states


Avoid adding illustrations to every section.


The primary visual language should remain clean and professional.


---


30. Abstract Visual Language


AquaWise can use abstract artwork based on:


- Water ripples
- Flowing water
- Organic shapes
- Leaves
- Droplets
- Circular flows
- Subtle gradients


The artwork should support the content rather than distract from it.


Avoid generic stock photographs whenever possible.


---


31. Animations


Animations should be subtle and purposeful.


Good examples:


- Smooth page transitions
- Chart loading animations
- Progress bar animations
- Button hover states
- Achievement unlock animation
- AI chat opening animation
- Small water/ripple motion


Avoid:


- Constant floating objects
- Excessive bouncing
- Large screen transitions
- Animations that slow down the application
- Animations on every element


The application should feel polished, not flashy.


---


32. Empty States


Empty states should provide useful guidance.


Example:


No Assessments Yet


«Complete your first assessment to start tracking your water usage.»


Button:


Start Assessment


Similarly:


No History Yet


Provide a clear explanation and action.


---


33. Error States


Errors should be understandable to normal users.


Instead of:


«"500 Internal Server Error"»


Prefer:


«Something went wrong while loading your data.»


Then provide:


Try Again


Technical details should be logged for developers rather than displayed to users.


---


34. Accessibility


The UI should consider accessibility from the beginning.


Requirements:


- Good color contrast
- Readable text
- Keyboard navigation
- Visible focus states
- Labels for form inputs
- Meaningful button text
- Icons should not be the only way to communicate meaning
- Charts should have supporting text/data where practical


---


35. Design Consistency


Every page should use a consistent design system.


Maintain consistent:


- Colors
- Typography
- Border radius
- Button styles
- Card styles
- Icons
- Spacing
- Form components
- Navigation
- Shadows


Do not create each page as a completely different design.


---


36. Design System


The implementation should establish reusable components such as:


- Navbar
- Sidebar
- Button
- Input
- Select
- Card
- Chart container
- Badge
- Achievement card
- Recommendation card
- Modal
- Toast notification
- AI chat button
- AI chat panel


Reusable components should be preferred over duplicating styles.


---


37. UX Principles


AquaWise should follow these principles:


Clarity


Users should understand what the interface is asking them to do.


Simplicity


Avoid unnecessary complexity.


Feedback


Users should receive feedback after important actions.


Consistency


Similar actions should behave similarly throughout the application.


Progressive Disclosure


Show essential information first and detailed information when the user requests it.


Trust


Water calculations and recommendations should be presented clearly, with explanations where appropriate.


---


38. Professional Product Rules


The AI development/design agent must follow these rules:


- Do not create a generic template.
- Do not overload the interface with cards.
- Do not use excessive gradients.
- Do not use blue and green on every component.
- Do not use excessive rounded containers.
- Do not use huge headings everywhere.
- Do not add unnecessary animations.
- Do not use random decorative elements.
- Do not sacrifice readability for visual effects.
- Keep spacing consistent.
- Keep charts readable.
- Keep the dashboard minimal.
- Maintain the same design language across all pages.
- Prioritize usability over decoration.


---


39. Recommended Page Visual Hierarchy


The application should follow this hierarchy:


Authentication


Brand → Purpose → Form → Primary Action


Assessment


Progress → Question Group → Inputs → Navigation


Results


Main Number → Score → Breakdown → Recommendations


Dashboard


Current Status → Trend → Recommendation → Detailed Analysis


History


Timeline/List → Comparison → Details


AI Assistant


Conversation → Context → Quick Actions


---


40. Final Design Vision


AquaWise should feel like a polished environmental technology product.


The visual identity should combine:


Water + Nature + Data + AI + Simplicity


The application should not try to impress users by adding as many visual elements as possible.


Instead, it should create a strong impression through:


- Clean layouts
- Thoughtful spacing
- Restrained blue/green branding
- Meaningful visualizations
- Smooth interactions
- Clear information hierarchy
- Professional typography
- Useful personalization


Core UI/UX principle


«Show the user what matters first. Let them explore the details when they want them.»


The final experience should make the user's journey feel like:


Login → Assess → Understand → Improve → Track → Achieve
